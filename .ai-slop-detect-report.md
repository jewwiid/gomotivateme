## Cross-template patterns (cross-file)

### Brand-word "momentum" — now mostly clean
"Momentum" survives in **2 user-visible strings** and a handful of component / aria-label names:

- `components/OwnerGoalWorkspace.tsx:254` `aria-label="Goal momentum"` (stat-block a11y label)
- `components/OwnerGoalWorkspace.tsx:520` body text: "Add the people and reasons that keep you going **when momentum dips**."
- `app/o/[handle]/[slug]/page.tsx:197` aside body: "Encouragement and thoughtful check-ins turn intention **into momentum**."
- `app/o/[handle]/[slug]/page.tsx:330` `aria-label="Goal momentum"` (same stat block as owner page)
- Component names: `MomentumStats`, `MomentumStat` (used as imports in 3 files; not user-visible)

The component identifiers are fine to keep (they're the literal stat-block name and would be churn to rename). The two body uses are real, not decorative — "momentum dips" is the natural phrase for "you've gone quiet on a goal" and "intention into momentum" is the right metaphor for the support model. **Recommendation: leave as-is.** If a stricter pass is wanted, only `o/[handle]/[slug]/page.tsx:197` is replaceable ("Encouragement and check-ins keep the goal moving.").

### "Be the first..." empty-state kicker — still 4+ instances, on-brand

Five files, five slightly different framings — varied enough to feel situational, but the rhythm repeats. **Recommendation: keep** (per prior audit decision; the variation is doing real work).

### Per-role label dictionaries — duplicated 4× (code, not copy drift)
Same `ROLE_META` dictionary (label / description / icon per support role) is redeclared in 4 components with subtle drift:

- `components/MotivationCircleManager.tsx:25-38` — labels: Encourager / Accountability / Advice / Review / Challenge
- `components/MotivationCircleWidget.tsx:17-30` — labels: Encourager / Accountability / Advice / Review / Challenge
- `app/o/apply/[goalId]/page.tsx:27-61` — labels: **Encouragement** / Accountability / **Practical advice** / **Progress review** / **Join the challenge** (substantively different)
- `app/invite/[token]/page.tsx:24-58` — labels: Encourager / **Accountability partner** / **Experienced adviser** / **Progress reviewer** / **Challenge partner**

This is **a copy-drift risk**, not a one-file slop problem. The apply/invite versions use the more descriptive "long form" labels ("Experienced adviser", "Progress reviewer", "Join the challenge") while the manager/widget versions use the short form. The user sees both forms in adjacent screens (invite → accept → manage circle), which feels inconsistent.

**Recommendation:** pick one canonical long form (the invite page's "Experienced adviser / Progress reviewer / Challenge partner" reads better for first-time visitors), apply to all four files, and consider extracting the dictionary to `lib/supportRoles.ts` so the labels can't drift again.
